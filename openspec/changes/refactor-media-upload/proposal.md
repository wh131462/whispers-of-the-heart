## Why

当前头像、Logo、封面、编辑器媒体和媒体库分别实现了上传请求与文件选择，存在两套媒体选择弹窗、重复的 `FormData` 逻辑，以及 `type`/`mimeType` 查询参数不一致的问题。现在统一上传契约和选择流程，可以在不改变现有存储方式的前提下减少重复代码，并让所有服务端媒体入口获得一致的鉴权、校验、错误处理和回归路径。

## What Changes

- 在 `@whispers/utils` 提供统一的媒体列表、单文件上传、批量上传和媒体 URL 类型契约。
- 统一 `/media` 查询筛选参数，兼容现有调用并修复选择器的筛选失效问题。
- 将前端服务端媒体选择收敛为一个响应式选择弹窗，支持图片、视频、音频、文档、搜索、分页、预览和上传。
- 迁移头像、Logo、博主头像、友链头像、文章封面、作品图标/封面、编辑器和媒体库入口。
- 编辑器通过注入的上传函数工作，不再直接拼接上传 URL 或绕过共享 API 客户端。
- 后端统一上传用途、类型和大小校验，保留现有本地 `uploads` 存储与媒体去重行为。
- **BREAKING**：前端媒体选择回调统一返回媒体对象；旧的 `packages/ui` `MediaPicker` API 不再作为业务入口。

## Capabilities

### New Capabilities

- `media-upload`: 统一服务端媒体上传、查询筛选、错误处理和前端媒体选择契约。

### Modified Capabilities

<!-- 当前没有已沉淀的媒体上传 spec；P2P 文件传输保持独立，不修改其契约。 -->

## Impact

- 影响 `apps/api/src/media`、`apps/web/src/components`、用户/管理后台页面、BlockNote/评论编辑器和 `packages/utils`。
- 不新增依赖，不迁移 MinIO，不改变数据库模型或现有 `/media/upload` 路径。
- 需要验证 API 类型、Web 类型、Lint、共享包构建、API 测试、Web 构建，以及上传/选择/头像/封面/编辑器的真实回归链路。

## Non-goals

- 不重构 P2P 文件传输、Base64 工具、音视频播放器的本地文件读取。
- 不实现图片裁剪、断点续传、分片上传、上传队列或对象存储迁移。
