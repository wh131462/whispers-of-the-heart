## Context

共享连接层已有 Socket.IO 信令和游戏消息转发，但聊天/文件要求 DataChannel。现有 metadata/chunk/progress/finalize/verification 协议不依赖具体网络通道。

## Goals / Non-Goals

目标：无需 TURN 或新域名，在直连失败时自动中转，完整性与页面内续传保持有效。
不新增加密协议、数据库或游戏规则。

## Decisions

- 使用独立 `relay` 事件并在 join/成员事件声明 `relayVersion: 1`。保留旧游戏 `message` 行为；旧客户端仅允许直连，避免升级期间误报可用。
- 每个成员有 3 秒直连窗口，之后中转可用；DataChannel 打开后优先直连。中转资格不随 ICE 重试清空，断开 Socket 或成员会话改变时清空。通道切换可能重复/乱序，由现有分块索引与最终校验保证恢复。
- 新增异步可靠发送 API，返回成功/失败，分块必须等待发送结果。中转按 Peer 排队、有界缓存和有限重试，接收端 ACK 表示接收了协议包；业务完成仍必须获得最终 SHA-256 校验。
- 服务端每包至多 32 KiB，每 Socket 至多 8 个转发中、每秒至多 2 MiB；只向同房间当前 Socket 会话转发，目标不可写或未确认时返回失败，不积累离线内容。
- UI 区分入房、建立通道、直连与中转；明确中转内容经过业务服务器，不承诺端到端加密。业务服务器不保存聊天/文件内容。

## Risks / Trade-offs

- 中转占用业务服务器带宽 → 消息大小、速率、并发和客户端队列有界。
- 网络或 ACK 丢失 → 有限重试，协议幂等，断线保留内存 checkpoint；最终校验丢失时重新发送 metadata/finalize。
- 房间仍为单实例内存 → 不宣称支持多副本；刷新页面不保留文件。
- 中转吞吐低于直连 → 保持直连优先，明确显示中转。

## Migration Plan

先更新 API，再更新 Web；无数据库迁移。旧客户端不使用中转。移除 TURN 配置并将旧变更的中继验收标记为被本变更替代。生产部署与真实跨运营商验收不由本地测试代替。
